It plans before it builds

A vague request is measured. A big one is split into a plan whose criteria name their proofs before any code exists. The builders never see the hold-out tests: no brief carries them, no sandbox holds them. One blind run, then the gate opens them, and a red one goes to an audit that names the defective side: the test, the code or the spec.

It does not stall

The sandbox is the guardrail

Each task runs in its own throwaway pod with its own identity. The network is closed except for named hosts. The agent never holds a push token. No prompt rule stands in for a wall.

11

Three layers: the factory, your process, your prompts

The base layer is the factory: sandboxes, workflows, gates. It works out of the box and runs on rented commodity servers. Everything you configure is a file. The development process is one: lanes, stages, merge rule. Ours is spec-driven; if you don't like it, bring your own, with a floor of checks and gates every process keeps. The prompts sit in your project's AGENTS.md: ours seeds it, you change it. The harness in the sandbox is an adapter behind one interface.

How it works

Built by construction

Reliability comes from how an AI step is built, not from its prompt. Every guarantee lives in a schema, a check, a gate or a route.

Reliability by construction, not by prompt

Every guarantee lives in a schema, a check, a gate or a route. A prompt rule is the last resort.

The factory builds itself

The roll is a card on its own board. Every commit carries the task, the session, who asked and who approved as trailers.

Hold-out tests graded blind

A separate session writes tests no sandbox can see. A red one goes to an audit with three verdicts: wrong test, real gap, spec question.

Outsiders' issues are screened

Screened for injection before any session runs. Issue text is scrubbed on the way in, agent text on the way out, secrets redacted from audit rows.

The console was designed by image models and a critic

Every image has a sidecar with its model, prompt and cost. The method is the same as the factory's.

Tradeoffs we made

  • gVisor, not a microVM, so cheap commodity servers are enough.
  • Roadmap intake as linked Markdown, not Jira: we think Markdown is better, and a Jira adapter would be easy.
  • Models are commodity APIs behind the gateway, like servers from Hetzner. Self-hosted LLMs fit behind the same gateway.
  • Signals arrive from Forgejo and SigNoz: Forgejo speaks GitHub's protocol, SigNoz is the open telemetry stack we picked.

    For investors

    The problem

    Regulated industries are locked out of autonomous development. In banks and medtech firms, pilots of autonomous agents die in the compliance review: the work would run in a vendor's cloud, decisions are unauditable and nothing is reproducible. Writing assistants leave the team size unchanged. Closed platforms cannot pass the review. An in-house factory is a multi-year platform project.

    The gap

    What exists are closed vendor services, and open building blocks and boards without the factory: no gates and no feedback loop. None of the 148 tools we surveyed ships the whole loop. This one is open source and self-hosted, with policy enforced by code instead of by the AI. The control plane, the sandboxes and the code stay on your servers; the models sit behind a gateway, so the model is your choice. Every model call, tool call and commit is attributed. It is rebuilt from the repository and a backup bucket, rehearsed on 13 October.

    The status

    Design complete, core built, in daily use: it develops all of the author's current projects, from games to home tools. Three services in Go: the control plane, the model gateway and the agent workers. On 21 October 2026: 233,425 lines of Go, 279 test files and 3,467 commits across three repositories since 24 September. A live cluster of three rented commodity servers was verified on 13 October 2026.

    Who built it

    One person. The architecture and every design decision are mine, I wrote the specifications, and I directed the AI agents that wrote much of the code, reviewing and ruling on every step.

    How it was designed

    The console's look was designed in rounds. Image models went wide, an independent vision critic judged, Sebastian picked, and code followed. Every generated image carries a sidecar with its model, prompt and cost. See the design rounds.
