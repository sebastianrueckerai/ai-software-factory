# Prototypes

One folder per direction, one `index.html` each: plain HTML, CSS and JS in the file, no build step, no framework, no network request (fonts are system stacks or `@font-face` from `../fonts/` if a direction needs one). Open the file in a browser. Every prototype shows the same data from [scenarios.js](scenarios.js) and keeps every control of [../inventory.md](../inventory.md), so the versions differ in design only. The direction's theme in `../themes/<slug>/DESIGN.md` is the rule set and its round images are the target. [../ia.md](../ia.md) is the floor: the direction may bend it where its theme says so, never below it.

## Mechanics every prototype has

1. **Scenarios.** `<script src="../scenarios.js"></script>` and a render function that draws the whole screen from `window.SCENARIOS[name]`. A small switch (top right, in the direction's own language, quiet) steps through busy, idle, fire, quiet; `?scenario=fire` in the URL selects one on load. Default busy. Counts, the pulse, the status figures and the chat all come from the data.
2. **Themes.** Dark and light on `data-theme` on `<html>`, a toggle in the top bar, `?theme=light` selects on load, localStorage remembers. Both themes are one design in two moods. Contrast floor: 4.5:1 text, 3:1 pill fills, colour never the only signal.
3. **The hierarchy.** Pulse on top, chat as the main affordance, board quiet. The two Needs you items in busy are the loudest things on the screen; a done card is one or two lines.
4. **The board.** Five columns (Needs you, Queued, Working, Verifying, Done) with counts. Card faces per `ia.md`: ref and title, state row, activity line only when working or waiting, chips only when exceptional, actions as quiet visible buttons. Needs you items with their real actions: Approve as you, Deny (opens the reason box with the request-changes or reject choice), Split; the escalation's choice buttons and "Or in your words"; a capped card's "Grant one session with this answer". Clicking an action shows a one-line confirmation in place (no backend).
5. **The drawer.** A click on a card title opens the drawer docked at the right edge over the board, never over the chat, 46 percent wide, at most 720 px, full screen on a phone. Escape closes. Tabs Overview, Chat, Activity, Files. Overview: the four-line top block, then the open need, then the collapsed sections (Objective, The agent's summary, The plan, Reviews and audit, Related cards, Edit, Links). The busy scenario's `drawer` object has the data for #601; other cards open with their face data and "no session yet" where data is absent.
6. **The chat.** Header with "project agent · project", New conversation, the old-conversations select. The log from the scenario: your bubbles, agent replies, tool blocks collapsed (name, duration, result on open), the proposal with Do it (primary) and Skip; clicking Do it turns it into an "applied" line with undo. The composer: a textarea (Enter sends, Shift+Enter breaks) and Send; a sent message appends as yours and the agent answers one canned line after a short typing indicator. "This is your own conversation" line stays.
7. **The top bar and pages.** Home word, project select, the links Board, New task, Projects, Resources, Costs, Policy, Alerts (links to `#`), theme toggle, user, Log out. The keys overlay on `?`. The wide view link may open a second layout or be present as a control that says "wide view" in the direction's language.
8. **Responsive.** Works at 1920, 1440 and 390 wide. Under 900 px: one column, chat first with its composer, then the board as stacked sections with Needs you first and Done collapsed. No horizontal page scroll.
9. **Accessibility basics.** Landmarks, headings, buttons are buttons, focus visible, the drawer is a dialog with focus moved in and restored, reduced motion respected.
