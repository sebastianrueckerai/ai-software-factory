# Board research: Nimbalyst

## Header

- Product and URL / repository: Nimbalyst — https://nimbalyst.com / https://github.com/nimbalyst/nimbalyst
- License, price model, self-host or free tier: MIT for the desktop and mobile apps (collab server AGPL). Individual plan $0 free forever, no account, no card; Teams $20/user/month or $200/user/year (free during Beta); Enterprise custom (collab server in your own Cloudflare account, data residency, governed model gateway). AI is bring-your-own: Claude Code / Codex subscriptions, API keys, or local models; no usage-based AI fees. ([pricing](https://nimbalyst.com/pricing/))
- Alive? Very. Release notes for v0.79.1 dated 2026-09-30; 614 open issues with daily triage; ~1.8k stars; the founder posts weekly Show HN iterations.
- Studied how: studied from a clone at 9f13b2794d6d37ab005af6302cfe2a8540cfcdb6 (v0.79.1) plus the real UI driven live: the renderer refuses a plain browser (it awaits `window.electronAPI` from the preload before it renders anything), so the app was run under xvfb and driven over its CDP port with Playwright, keyless, and its SQLite session store seeded with ten realistic sessions. Studied on 2026-10-02.
- One sentence: an MIT Electron "visual workspace" (Obsidian-like docs plus an agent chat) whose Session Kanban treats Claude Code and Codex sessions as cards on phase columns, for a solo developer or small team steering many local agent sessions at once.

## 1. The board model

- Columns: fixed five phases — Backlog, Planning, Implementing, Validating, Complete — plus an Inbox for unphased sessions and an Archive gutter. Their own words: "Organize sessions on a kanban board by phase". Column colors are fixed semantics (gray, blue, yellow, purple, green). Any column can collapse to a thin vertical strip, and collapsed columns still accept drops. `docs/FEATURE_INVENTORY.md` claims "configurable columns"; at this commit the phase list is a constant in code, so treat configurability as aspiration. Only root sessions appear; children of a workstream live inside the parent's card.
- Card anatomy (top to bottom, verified in `SessionKanbanBoard.tsx` and visible in [app-board-populated.png](shots/nimbalyst/app-board-populated.png)): type/provider glyph (Claude star vs Codex hexagon); title, two-line clamp; a live status badge (waiting, running); unread dot; for workstream cards, a child count ("3 sessions") and a ChildRunStateBar — a segmented bar counting children running / waiting / review / idle / done; up to four tag chips plus "+N"; footer with uncommitted-file count, a peek button, and relative time ("45m ago"). Nothing hides behind a click on the face itself; the whole card is click-to-open and right-click for a context menu (rename, archive, set phase, set tags). What never appears on the board: the transcript, diffs, cost, elapsed time, model.
- Where decisions live: on the transcript, not the board. A waiting card shows a "1 waiting" badge and the top bar shows "N awaiting input session(s)"; opening the card scrolls to the interactive prompt (AskUserQuestion, plan approval, GitCommitProposal, ToolPermission) inline in the transcript. From board to approve: click card, click the answer — two clicks, zero navigation. A cross-session "needs you" list exists in the Agent navigation badge (sessions awaiting input, running, unread, grouped) and, off-desktop, on the phone's Live Activity ranked by longest-waiting.
- Filters: title search, tag chips with counts, show-complete toggle, archive filter. One board per workspace; no cross-project view. Per-column sort is updated-at descending, not configurable.

## 2. Agent-task specifics

- While it runs: the card's badge reflects live session state (running / waiting_for_input / idle) pushed over IPC — no polling. No progress percent, no elapsed time, no cost anywhere on the card. What changes on finish: status goes idle, the unread dot lights if you missed it, an OS notification fires, and — the notable automation — a commit whose message closes a linked tracker item marks the session's phase `complete` automatically (`interactiveToolHandlers.ts`, CommitTrackerLinker → `applySessionMetadata({phase:'complete'})`). A question flips the badge to waiting and, when the phase moves to complete, the pending-prompt flag is cleared by normalization.
- The conversation lives behind a hover: dwelling on the card's peek icon for ~300ms (or pressing Space on the focused card) opens a transcript popover — the last 100 messages rendered in compact mode, tool calls collapsed, and it live-streams while the session runs (refresh debounced 1.5s on the transcript signal). The docs pitch it as showing "the recent context of long turns, not just the trailing tokens", and the popover footer summarizes "Finished in 32m 0s · 1 file". A workstream card's peek resolves to its most recently updated child — hovering the epic shows you what is actually happening inside it. Verified live in [app-card-peek.png](shots/nimbalyst/app-card-peek.png) and [app-workstream-peek.png](shots/nimbalyst/app-workstream-peek.png).
- Steering mid-run: not from the card. One click opens the session in Agent mode where you type (prompts to a busy session queue and run in order), interrupt, or stop; a coordinating workstream session can interrupt a child to deliver an instruction immediately. The board itself is read-plus-reorganize.
- Approvals and spend: tool permissions, plan approvals and commit proposals are interactive prompt cards in the transcript (durable across restarts), each answerable on the phone. Spend is invisible on the board — BYO keys means per-provider usage dashboards exist elsewhere in the app, and the card surfaces only a rate-limit warning (amber) / blocked (red) widget when the provider throttles. No budgets on the card.
- Parallel agents: this is the product's center of gravity. Each session keeps its provider glyph, so a mixed Claude + Codex board reads at a glance; workstream cards roll child state into the segmented bar and a "1 waiting" badge; the workstream's own phase is derived from its most active child (implementing > validating > planning > backlog > complete). Sessions can also be born as worktrees, and worktree cards get their own card type.

## 3. Interaction model

- Moving work: drag and drop, multi-select aware (Cmd-click, Shift-click, Cmd+A, then drag all); dropping writes `metadata.phase` through an optimistic atom that reverts on IPC failure. Keyboard moving exists too: Cmd+Arrow moves the selected card(s) between phases. The same write path is exposed to the agent as the MCP tool `update_session_meta`, so the agent moves its own card; every transition is appended to a per-session activity log (capped at 100 entries, `status_changed` / field `phase`). And the `/session-cleanup` skill (Planning extension) audits the board and proposes phase corrections and archive candidates as a checkbox list for approval — agent-assisted board hygiene.
- Keyboard: Cmd/Ctrl+Shift+K opens the board; arrows move focus across cards and columns; Enter opens; Space peeks; Escape backs out. Mobile: the board itself is desktop-only, but the iOS companion mirrors the "needs you" surface — push when a session completes, errors, or needs approval (suppressed while you are active at the desktop), reply by text or voice, queue prompts offline, approve tool permissions / plans / commit proposals, start a session remotely on the desktop machine; diff review stays desktop. Sync is end-to-end encrypted (AES-256-GCM per message, QR-paired keys that never touch their servers).
- Refresh model: event push throughout — session registry and transcript signals over IPC; the peek streams; nothing on the board requires a reload. The one polling-shaped thing (workspace file watching) is invisible to the board.
- Click map from the board: read status — 0 clicks (badge on the face); read detail — 0 clicks (hover peek) or 1 click (open session); decide — 2 clicks (open, answer the prompt card); steer — 2 clicks plus typing (open, send message); comment — 2 clicks (open, send); there is no steering box on the card face itself.

## 4. Visual system

- Themes: dark is default (six built-in themes, dark/light/system). Colors are strictly split: system-set semantics for state (phase column colors, the amber waiting glyph, green complete), user-set content left neutral (tags are quiet gray chips on white/6%, never colored). Provider identity is the one brand-color exception (Claude vs Codex glyphs).
- Typography and density: 12px card titles, 10-11px metadata; a card is roughly 40-60px tall, so a 1000px-tall window shows 8-12 cards per column — the whole ten-session workspace fits one screen ([app-board-populated.png](shots/nimbalyst/app-board-populated.png)). Cards read fine as thumbnails: title, badge, tags, time always present.
- Status vocabulary, exhaustive: five phases (column position + colored dot in the header) — plus Inbox (no phase yet), Archive; run status idle / running / waiting_for_input (badge); waiting-children count (help glyph + number); unread (dot); child states running / waiting / review / idle / done (segments in the rollup bar); archived (out of all columns but complete); pinned (list view). Phase and run status are two orthogonal axes on every card — the workflow lane does not move because the agent paused, and vice versa.

3. Depth beyond the CLI for non-code work — "Nimbalyst is much more than just a GUI on the CLI... Files Mode where you can work with your agent in markdown, mockup, excalidraw" (same r/Nimbalyst thread); also "pretty good for this. At least better than alternatives I've found" for business/non-product work ([r/Nimbalyst](https://www.reddit.com/r/Nimbalyst/comments/1uzdjfv/who_else_is_using_nimbalyst_for_businessnon)).

Complained (the repo's 614 open issues are the honest signal; reactions are thin, so "common" reads as recurring themes):

1. Resource weight and freezes: "Main process freezes 7-18s on every agent switch" scanning plugin node_modules ([#1641](https://github.com/Nimbalyst/nimbalyst/issues/1641)); "~3.5 GB / 100% CPU... when thousands of binaries change" ([#1619](https://github.com/Nimbalyst/nimbalyst/issues/1619)); "Silent crash during long sessions as the FileSnapshotCache floods" ([#1599](https://github.com/Nimbalyst/nimbalyst/issues/1599)).
2. Worktree/Codex roughness: "[Bug]: Incredibly rough experience with Codex. 'read only' workspaces, broken worktrees" (issue title on the [issues page](https://github.com/Nimbalyst/nimbalyst/issues)); "worktree session's working directory reverts to the main checkout" ([#1624](https://github.com/Nimbalyst/nimbalyst/issues/1624)).
3. Question/permission plumbing edge cases: clicking "Allow Once" on a compound-command fragment "reaches the agent as a denial" ([#1612](https://github.com/Nimbalyst/nimbalyst/issues/1612)); an interrupted question card "stays pending forever" ([#1617](https://github.com/Nimbalyst/nimbalyst/issues/1617)); quitting with an active session crashes the app (top of the issues page).

Caveat: independent criticism is scarce; much of the Reddit visibility is founder-posted, and the HN threads are small (8-29 points).

## 6. Verdict for us

- **Steal**:
  - Phase lane orthogonal to live status — the card's column says where work is in its lifecycle, the badge says what the agent is doing right now; neither overwrites the other. One line: two independent state axes per card, fed by different sources (human/agent-set phase, harness-fed status).
  - The hover-peek transcript: last-100 tail, compact rendering, live-streaming while running, "Finished in 32m · 1 file" footer, and workstream peeks resolve to the most recently active child. One line: dwell or Space on a card opens a streaming transcript popover, no click needed.
  - Workstream rollup: child-count + segmented child-state bar + "N waiting" badge on the parent, phase derived from the most active child. One line: parent cards summarize children; you only open what needs you.
  - Inbox column for the unphased: new sessions land in a triage lane instead of faking a phase. One line: no phase, no column — an Inbox absorbs arrivals.
  - Agent-writable board hygiene: `update_session_meta` MCP tool, commit-closes-tracker-item auto-completes the phase, and the `/session-cleanup` skill proposes corrections as an approval checklist. One line: the agent maintains its own card, and audits are proposed, never auto-applied.
  - Smart push routing: phone notifications only when the desktop is idle; a Live Activity ranked by longest-waiting session. One line: notify where the human is, and rank by how long it has waited.
- **Skip**:
  - Decisions only in the transcript: no approve/deny on the card face, no cross-project "needs you" board. Our stage10 items 20/24 want the reason on the card and one keypress to clear.
  - No cost, elapsed time or progress on the card (BYO keys make spend invisible). We need item 41/42 (budget warnings, stop-reason states) on the card.
  - Phase stored as a loosely-typed metadata blob read through two shapes (`metadata.metadata?.hasUnread ?? metadata.hasUnread`) — a schema lesson: one normalized column, one shape.
  - The Electron-desktop-only shape: local files, local execution, computer must stay on. The exact opposite of our substrate; copy the UX, not the architecture.
- **Decision needed** for the aggregate: who moves a card — Nimbalyst lets both the human (drag) and the agent (MCP tool) write the phase, with an agent audit proposing corrections; cline/kanban derives columns purely from harness state. Mutually exclusive philosophies: writable board vs derived board.
- Cloneability: trivially cloneable — MIT, `npm install && npm run dev` in `packages/electron`, runs keyless (onboarding has a Developer Mode path; the board renders with zero provider keys), SQLite on disk is seedable (this report's screenshots were produced exactly that way). The iOS app's push/relay needs their beta account; everything board-relevant is local.

## Scoring axes

| Axis | Score | Reason |
|---|---|---|
| Card scannability (read ten cards in one glance) | 4 | Compact cards, title+badge+tags+time always present; provider glyphs distinguish agents; no status text, only icons. |
| State clarity (what is happening, how far, what next) | 3 | Phase and run status are crisp, but no elapsed time, progress, or cost anywhere on the card. |
| Human-decision surface (find and make the next decision) | 3 | Waiting badge and awaiting-input counter find it, the transcript prompt decides it in two clicks; no decision on the card face, no cross-project queue. |
| Agent-activity legibility (is the agent working, waiting, stuck) | 5 | Live streaming peek, running/waiting/idle badges, unread dots, child-state rollup — every mode is visible without opening anything. |
| Noise level (5 means quiet: nothing without meaning) | 4 | Card face shows only state-bearing signals; peek and transcript are opt-in; the fixed five columns stay clean. |
