## What exists

Verified on the code repository's `origin/main` at 3244774, 2026-10-15:

- **The write door.** `doWriteDoc` in `internal/console/autonomy.go`: the path allow-list (docs/roadmap.md, docs/plans/, docs/board/, docs/<name>.md), the size cap, the structure check on docs/roadmap.md, a lock per repository, the content-hash compare-and-swap on `base_sha256`, one commit on master through `Forgejo.CreateFiles` with the attribution trailers, under the docs writer token. `readDoc` reads through Forgejo's contents API and answers the text with its hash. The chat's `read_doc` and `write_doc` call them. The door is the one place that writes a document, and this plan keeps it so.
- **The member's identity.** Every console action runs with the member's own Forgejo token (5.7), so a save as the member is the same door with another token.
- **The drawer.** `templates/drawer.html` and `openDrawer` in `static/console.js`: docked at the right edge over the board, `min(46%, 720px)`, never over the chat, full screen under 900 px, the open card in the URL.
- **The event stream.** The `events` table with `via`, the feed and the SSE stream per project, the board's live badge. No event names a document write.
- **The push webhook.** `handlePush` in `internal/factoryd/intake.go` takes Forgejo's push events.
- **Rendering.** The console renders no Markdown today. `git` is in factoryd's image (the Dockerfile installs it). `go-difflib` is an indirect dependency; no three-way merge exists.

## Work items

1. **The read endpoint and the renderer.** `GET /projects/{name}/docs/{path}` answers the document rendered, with its content hash, its head commit and that commit's time; `?raw=1` answers the text; `?peek=1` the first paragraph as text. The renderer is goldmark, CommonMark with HTML escaped and raw HTML off, the one new dependency (the reference Go implementation, Forgejo's own). Links as the engine rules them: a relative target resolved against the document's directory that lies inside the roots becomes `<a data-doc="<path>" href="?doc=<path>">`, a target outside the roots or missing renders as text with a title, http(s) opens a new tab. Headings get ids. The document repository and its roots come from the project's backlog block for a user project and are the factory's own document repository for the factory's projects. The project's writers read; the factory's writers read every project, as 5.7's reads do. One row in the access table.
2. **The drawer's document mode.** `drawer.html` gains the document body and `console.js` its mode: the head (`‹ <label>` and `<label> ›` as the history's neighbours, Recent with the last six, the path with the indicator, Read | Edit, Open in Forgejo, Wide, New document, ×), the pins row, the article at `max-width: 70ch` in the console's text type at the chat's 14.5 px. `?doc=<path>` on the project page opens it; every open pushes the URL, `popstate` restores, the scroll per path is kept in `sessionStorage`. The peek on hover or focus after 400 ms, from `?peek=1`, never on touch. Pins live in the browser per project, the backlog file pinned by default, `+ pin` adds. Wide covers the board at the same 70ch centred, the chat never covered, Narrow returns. A card takes the slot; a "Documents" button in the board head reopens the document where it was. The phone: full screen, one column, 44 px targets, no Wide, no peek.
3. **The editor and the draft.** Edit swaps the article for a textarea in mono with the browser's spellcheck, the full height, and the editor row: Save as commit, Cancel, Discard, `based on <sha>` faint. Every keystroke writes the draft to `localStorage` under project and path. The indicator on the path line: clean with `<sha> · <time>` muted, `●` before the name from the first keystroke, `· saving…` while a save runs, the reason in the amber text colour when a save did not land. The pins, Recent and the Documents button carry the dot while a draft exists. Leaving with a draft shows no dialog; coming back reopens in Edit; a reload restores with `draft from <time> restored · discard`; Discard asks `Discard your changes?` inline. Ctrl+S and Cmd+S save. New document asks a name inline and opens `docs/<slug>.md` with its heading; the first save creates it.
4. **The save as a commit.** `POST /projects/{name}/docs/{path}` with the text and the base hash runs `doWriteDoc` with the member's token: the allow-list, the size cap, the structure check, the lock, the compare-and-swap, one commit on master with the message `<path>: edited in the console` and the trailers naming the member and `via: console`. The answer is the new hash, commit and time, or a refusal with its reason, the current text and its hash. The client runs the save in the background: one in flight, one queued with the latest text, the editor live throughout; typing during a save brings the dot back; a landed save clears the dot and shows the commit and time, staying in Edit if the member typed meanwhile, else returning to Read; a failed save shows `not saved: <reason> · retry`. The door raises one event `doc_written` (path, hash, commit, by, via) for every write it makes: the chat's tool, the close-out of the backlog plan, the member's save.
5. **The three-way merge at the door.** When the base hash is stale, the door fetches the base text by the base commit (`contents/<path>?ref=<commit>`), writes base, head and the member's text to a temporary directory and runs `git merge-file -p`. A clean merge is committed as the member's with the answer `merged with <who>'s change`, and the client shows the merged text. Conflict markers mean a refusal: `<who> changed the same lines (<time>)`, with the current text, its hash and the clashing line ranges; the client keeps the text and the dot, and "show theirs" opens the current text read-only under the editor with the clashing lines marked. The chat's `write_doc` keeps its passage edit and needs no merge.
6. **Outside changes reach the drawer.** `handlePush` raises `doc_written` for every changed path under the roots when a push lands on the document repository's master, deduplicated by commit against the door's own event. The drawer listens on the project's stream: an event for the open path shows, in Read, `changed by <who> <time> · reload` (reload re-reads and keeps the scroll), and in Edit, `changed by <who> <time> · your save will merge · load theirs`. Load theirs asks `Discard your changes and load the version of <time>?` inline before it replaces the text and clears the draft. The text never changes by itself.
7. **The lab and the check.** The console lab gains a document repository fake (the roadmap and two plans with real links, an outside change, a conflicting change) and the scenarios of the states. A Playwright check adapted from the round's `check.js` and `states.js` runs against the lab: every state's strings and the dot, every text pair at 4.5:1 in both themes, the chat never covered, Escape, no horizontal scroll at 390. The lab shoots the document states in both themes before and after each item.

## Order

Items 1 and 2 first, as one pull request: reading alone is already the larger half of what Sebastian lacks, and it needs no write. Then 3 and 4 together, since the draft and the save are one experience. Then 5 and 6, which make the save safe under concurrent change. Item 7 lands with each step. Each step keeps `go test ./internal/console/` green and the lab's structural check green.

## Verification

Hand-derived tests:

- The read endpoint renders a relative link inside the roots as a drawer link with the resolved path, a link outside the roots as text, an http link with a new-tab target, and escapes raw HTML in the source.
- A writer of the project reads; a member of another project gets 404; a factory writer reads every project.
- A save with a fresh base hash commits as the member, with the message and the trailers, answers the new hash and commit, and raises `doc_written` with `via: console`.
- A save with a stale base hash and a change on other lines commits the merged text and answers "merged with".
- A save with a stale base hash and a change on the same lines refuses with the current text, its hash and the line ranges, commits nothing.
- A save that breaks the roadmap's structure refuses with the finding, commits nothing.
- A save with Forgejo unreachable refuses with the reason, and the draft is untouched on the client.
- A push on the document repository raises one `doc_written` per changed path under the roots and none for a path outside them, and a push of the door's own commit raises no second event.
- The drawer: `?doc=` opens the document; a link opens its target and pushes the URL; the browser's back returns at the old scroll; the dot appears on the first keystroke and on the pin; a reload restores the draft; Ctrl+S saves; three Ctrl+S during a slow save make two commits; an event for the open path shows the changed line and changes no text; load theirs asks first.
- The check of item 7 passes in both themes at 1440 and 390.

Live: Sebastian opens the roadmap on the project screen, follows a plan, comes back, edits a line, presses Ctrl+S, and the commit lands on master under his name; the chat's agent edits the same file on other lines while he types, his next save merges; it edits the same lines, his save is refused and show theirs shows the clash.

## Not in this round

- The hybrid's two panes, the tabs, the tree rail. Sebastian's pick is the wiki alone.
- Presence or a lock while someone edits. The merge and the refusal cover it.
- Autosave to git. The draft lives in the browser, one Save is one commit.
- A commit message box. The message is fixed.
- Images and tables in Markdown beyond what goldmark renders by default; no attachments.
- Pins on the server, shared between a member's browsers.
- Editing outside the document roots, and the structure check on files other than the roadmap.
