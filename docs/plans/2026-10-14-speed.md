# Plan: the factory's speed round

The handover of 2026-10-14 ([2026-10-14-speed-handover.md](2026-10-14-speed-handover.md)) names the goal: many small tasks, each visible from plan to merge, each merged minutes after green, and the factory updating itself without stalling. No batch merges. The queue stays serial. The fix is a cheap turn. Six items land in order, each with its own roll and its own live verification. Sources: the handover, roadmap 222, 157, 225, 227, rulings 269, 205, 208, 299, 109, 322, and the four code traces of this session.

## What the traces established

- factoryd never talks to opencode. The agent-worker in the pod drives opencode on loopback and streams events on stdout. factoryd follows the pod log (`followPodLog`, which reopens the stream and skips lines already seen) and posts to the worker's port 8091 (`/message`, `/push`) with a bearer token minted at pod creation. On a graceful stop, `shutdown()` deletes the pod, reads the worker's push of its work in progress, and the deferred cleanup deletes the namespace and revokes the task's tokens. Temporal retries `RunSession` on the new factoryd from the heartbeat details (session id, findings), and the retry starts a new pod from the branch head.
- The merge queue is `internal/factoryd/queue.go`. A roll enters it like any card, because the code project's process is `spec` with `merge: {queue: project}`. The five-minute timer in `queueTurn` is a backstop: `leaveQueue` signals the new head at once and the heal pass signals waiting heads every minute. The checks wait polls the combined status every 10 s. No webhook for check events exists.
- Review and audit read the diff only. The review prompt says the checks passed, pinned by a test.
- No handling of a red main exists. `annotateMainFailures` only suffixes a card's finding with "(also failing on main)".
- The gateway mints one LiteLLM key per session with both coding aliases on it, but refuses a call whose alias differs from `tasks.model_alias` (server.go:244). The in-session climb is therefore a gateway rule plus one opencode message: opencode reads the model from the newest user message on every turn (prompt.ts 1136 at v1.18.32), and the model must be declared in the provider block.
- `AttemptFunded` is passed the prefixed `factory/coding-cheap`, which no price table has, so it fails open on every attempt (live log: "LiteLLM has no model "factory/coding-cheap"; the attempt is not refused").
- Card size is a "Size:" line in the issue body, never a column. The lane collapse's `track` field does not exist on any branch.
- `schematest` already gives each test package its own database. `-p 1` dates from 2026-09-27 ("like the Makefile"). The CI pod has a 2 CPU limit (`ciLimits` in ci.go); the nodes have 8.
- Card 639 (in flight) makes the approval request wait for a green staged head. Item 4 defines the no-overlap case as green by the pull request head's checks, and the approval of 639 checks its guard against that.

## Work items

### 1. Rolls leave the merge queue

A roll never takes a project queue turn. `queued()` in queue.go answers false for a roll under change id `roll-no-queue` (`versionRollNoQueue`), so `stages()` goes straight to the approval stage. A roll merges without a sync: `block_on_outdated_branch` is off on main, only rolls touch `k8s/*.yaml`, and one roll task is open per repository. A fold still re-verifies and re-asks the approval, as today. The roll keeps its session gap until item 2.

Tests: `TestWorkflowRollTakesNoQueueTurn` in workflow_roll_test.go (a roll under `queue: project` reaches the approval with no `EnterQueue` and no `SyncWithMain`), `TestQueueOneAtATime` unchanged for cards. Live: a roll approved while sessions run waits in its gap (`roll_waiting` on its timeline) and a card at the queue head gets `queue_turn` and merges past it.

### 2. Sessions survive a factoryd restart, so a roll needs no gap and no hold

The reattach, by construction: the pod outlives factoryd.

- A `live_sessions` row per running session (migration): task id, session id, namespace, pod, message token, started and deadline, the count of pod-log lines consumed. Written when the pod starts, updated at every heartbeat tick and exactly at a detach, deleted on every real end.
- Detach: the worker-stop case in `runSession` no longer calls `stop(TripShutdown)`. It writes the row's line count, stops following the log and returns `errWorkerStop`. The deferred cleanup (pod delete, namespace, token revoke) is skipped on a detach, nowhere else. Cancel, trips, the wall clock and the gate supervisor's retry end the pod as today.
- Reattach: `RunSession` reads the task's `live_sessions` row first. With a row and a running pod it skips the token revoke, the namespace and the pod creation, registers the pod in the runner's maps (`trackPod`, `liveSession`, `sessionRuns`), continues the same session id and recorder, keeps the recorded deadline and follows the log from the recorded line. With a row and a dead pod it deletes the row and runs today's path, the heartbeat's findings included. The session supervisor's windows restart at the reattach (noted, not fixed).
- The maps are rebuilt from the rows by the retried activities themselves: Temporal retries `RunSession` within seconds of the new worker's start. `sessionOptions` gets `MaximumAttempts` 10, since every restart costs one.
- The agent's pending question: the gateway's `Factoryd.Escalate` client retries a refused or unreachable factoryd for up to two minutes, inside the MCP tool's 150 s timeout, so an ask raised during the restart lands on the reattached session.
- The gate supervisor's wait and retry stay in-process timers. The interceptor re-arms them on the retried attempt, and the session's own deadline is the bound that matters. Converting them to workflow timers would change every running workflow's history for no measured gain. Recorded as a decision.
- Then the gap and the hold go: `roll-gap` gets `versionRollNoGap`. A new roll merges at once after its approval, a new session waits for no hold, `RollGapNote` leaves the card. `AwaitSessionGap`, `AwaitRollHold`, `ClearRollHold` and `roll_holds` stay for the workflows started under version 1 and go in a later cleanup. `rollBoot` has no other user.

Tests: `TestRunSessionDetachKeepsThePod` (worker stop: no pod delete, no revoke, the row's count), `TestRunSessionReattachesToTheLivePod` (a row and a running pod: no new pod, the log followed from the count, the same session id), `TestRunSessionReattachFindsADeadPod` (today's path), `TestWorkflowRollMergesWithoutAGap`, `TestWorkflowSessionWaitsForNoHold` under the new version, the gateway's `TestFactorydEscalateClientRetries`. Live: `kubectl rollout restart deploy/factoryd` under a running card; the session's pod stays, factoryd reattaches (`session_reattached` on the timeline), the session pushes; a roll approved with sessions running merges within a minute.

### 3. CI under 2 minutes for a console change, under 4 for a factoryd change

- `pr.yml` test job: `go test` with the affected packages, no `-race`, no `-p 1`. Each package has its own database already.
- The runner image carries the module cache and a warm build cache: `Dockerfile.runner` runs `go mod download` and compiles every package's tests (`go test -run '^$' ./...`) at build, as the runner user, into `GOMODCACHE` and `GOCACHE` the job reuses. Main CI rebuilds the image on every push on the layer cache, and the roll pins it, so the cache is at most one roll behind main. `go.mod` and `go.sum` join the runner image's inputs in the `changes` map.
- The image-build job runs on a pull request only when an image's recipe changes: a Dockerfile, `.dockerignore`, `go.mod`, `go.sum`, or `opencode-plugin/`. A Go change under `cmd/` or `internal/` no longer builds images on the pull request: main CI builds them after the merge and item 4's backstop handles a red main. Recorded as a decision.
- The CI pod gets 4 CPUs (`ciLimits`, `ciRequests` 1, the namespace quota likewise) in ci.go: a factoryd change, rolled.
- `ci.yml` keeps `-race` on main and drops `-p 1`. A `nightly.yml` runs the full suite with `-race` at 03:00 UTC.

Measure: the test job's `run_started_at` to `updated_at` on the next console-only card and the next factoryd card, against the baseline's 5 min 38 s, and the gate's checks window on the card.

### 4. A cheap merge turn

Backstop first.

- Red main: the roller's poll already reads main's runs. A red push run of main newer than the last seen pauses the project's queue (`queue_pauses` row: project, run, sha, since, the fix card, the revert card) and files the fix-forward card through `FileAgentTask`, titled "main is red at <sha>: <failed jobs>", with the run's link and the failed job names. `EnterQueue` answers one more ahead while the project is paused and records `queue_paused` once; the pause's own cards are exempt. The next green run of main clears the pause and signals the queue heads. A pause older than two hours with no landed fix files the revert: a branch on the bot's fork with `git revert` of the red commit (`-m 1` for a merge), its pull request, and a factory-PR card through `FileFactoryPRTask`, exempt from the pause.
- The skip: after `SyncWithMain` moved the head, `queueTurn` compares the files main's new commits changed (`Compare` from the old merge base to main) with the pull request's paths (`g.Policy.Paths`). No file in common: no re-check, the approval request at once, and `Merge` reads the green status of the pull request head whose stages passed (`checkedHead`), not the synced head's. Files in common: the re-check as today, which the affected-package selection already limits to the pull request's packages.
- Review and audit start at the checks stage as futures (change id `gates-parallel`) and are taken at their stage's turn, so the findings keep their order. The review prompt's sentence about the checks changes to "the checks run beside this review".
- The queue's five-minute timer stays as the backstop it is: the new head is signalled at once by `leaveQueue` and within a minute by the heal pass. The checks wait's 10 s poll stays. Nothing to build.

Tests: `TestRollerPausesTheQueueOnARedMain`, `TestRollerFilesTheFixForwardCardOnce`, `TestRollerClearsThePauseOnGreen`, `TestRollerRevertsAfterTheBound`, `TestEnterQueueHoldsBehindAPause`, `TestSyncSkipsTheRecheckWithoutAFileInCommon`, `TestSyncRerunsChecksOnAFileInCommon`, `TestMergeReadsTheCheckedHead`, `TestStagesReviewAndAuditRunBesideTheChecks`. Live: a green small card merges within a minute of green.

### 5. The model tier

- (a) The starting rung at filing: `tasks.rung` (`cheap`, `frontier`, empty) and `tasks.size` as columns, read by intake from the issue body's "Rung: <rung>, <reason>" and "Size:" lines, which the chat's `new_card` (a `rung` parameter with a one-line reason) and the planner (`PlanCard.Rung`, `RungReason`) write. Without a line, intake derives it: size large, a plan card, or a "Directories:" line under `internal/factoryd/` start on frontier; everything else on cheap. `TaskConfig.Stronger` reads the rung. The policy's `models` list stays the bound (`fitsLadder`). The column sits beside `lane` and `process`, where the lane collapse's `track` goes.
- (b) A cheap first attempt has eight minutes to push: the session supervisor's `TripCheapCap` at start plus 8 min on the start rung without a push.
- (c) The climb inside the session: `TripCheapCap` and `retry_stronger` on the start rung switch the running session: factoryd sets `tasks.model_alias` to the stronger alias (the key already admits both), posts the worker a message with the stronger model id (the opencode config declares both aliases), records `model_switched` on the timeline and in `events`. At the top rung `retry_stronger` ends the session as today. `stronger_after` is 1 for medium and large cards (`TaskConfig.StrongerAfter` from the size), the limit's value for small.
- (d) `AttemptFunded` prices the alias without its provider prefix (`aliasOf`), and an unpriceable model refuses the attempt (fails closed) with the price error on the card.
- Measurement rows in `events`: `session_started` (model, attempt), `session_pushed` (model, minutes since start), `model_switched` (from, to, reason, minutes).

Tests: `TestIntakeReadsTheRungLine`, `TestIntakeDerivesTheRung` (large, factoryd directory, plan, small), `TestChatNewCardRung`, `TestPlanCardRung`, `TestSupervisorCheapCapTripsAtEightMinutesWithoutAPush`, `TestRunSessionSwitchesTheModelInSession`, `TestGatewayAdmitsTheSwitchedAlias`, `TestStrongerAfterBySize`, `TestAttemptFundedRefusesAnUnpricedModel`, `TestAttemptFundedStripsThePrefix`. Verify on ten cards: time to first push by rung, climbs, cost, from the new rows.

### 6. Cheaper subagents for expensive sessions

- In the harness: the gateway admits, besides the session's alias, any alias of the task's class that LiteLLM prices at or below it, so a subagent on `coding-cheap` runs through the task's own key and the ledger bills the task. The opencode config declares both aliases and sets `agent.general.model` and `agent.explore.model` to the cheap alias when the session runs on frontier. A child session's write tool parts count toward the parent's write clock in `serveMapper`, so a long subagent does not trip `no_write`.
- As cards: a `delegate` MCP tool (gateway) that posts to factoryd's `/internal/delegations`, which files a direct child card: the ready lane, class coder, rung cheap, size small, `parent_task` the caller, `source` delegate, a dependency on the parent (wait_until done), the brief the tool's text. Today's lane shape, the lane collapse's track shape when it lands.
- The work guide gets one sentence for both: routine, well-specified work goes down a rung, in session through the task tool's general or explore agent, after this card through delegate.

Tests: `TestGatewayAdmitsACheaperAliasOfTheClass`, `TestGatewayRefusesADearerAlias`, `TestOpencodeConfigSubagentsOnTheCheapRung`, `TestServeMapperCountsAChildWrite`, `TestDelegateTool`, `TestDelegationFilesAChildWithADependency`. Live: a frontier card's transcript shows a subagent on coding-cheap and the ledger rows on the task; a delegate child appears in the queue, waits on its parent, and starts when it lands.

## Rules of the round

Worktrees of `~/repos/ai-software-factory-code`, the main checkout untouched. Each item: a branch, `go test ./...` green locally, a pull request for CI, a controller-direct merge to main (precedent 222a), the roll approved in the console as controller, the live verification, the decision in the roadmap. No batch merges. Reports and commits follow the writing guide.

## Not in this round

Batch merging, a second factoryd replica (157), the lanes collapse (225), the console design (227), the gate supervisor's timers as workflow timers (above), the removal of the version-1 roll activities and the `roll_holds` table.
